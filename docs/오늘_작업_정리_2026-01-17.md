오늘은 주로 4개의 주요 기능에 대한 스펙 문서 작성 및 일부 구현을 진행했습니다. 미디어 로드 이후 Diff 계산 개선, 삭제 로직 정제, 카메라 비교 옵션 추가, 상세 뷰 제거 연구, 그리고 GroupManager의 컬럼 내 순서성 체크 로직 개선을 다뤘습니다.

## 주요 작업 항목

### 1. 미디어 로드 이후 Diff 계산 개선 (abnormal_diff_after_media_load)

#### 1.1 문제 분석 및 요구사항 정의
- **문서**: `docs/spec/abnormal_diff_after_media_load/01_requirements.md`
- **문제점**: 
  - Normal 이미지 라벨의 `(Diff: ...)` 정보가 간헐적으로 누락됨
  - 파일이 쓰이는 중(락/부분쓰기)인 순간에 `CheckAbnormalStatus()`가 실행되면서 이미지 치수 판독 실패
  - Diff가 캐시되지 않은 채로 화면이 갱신됨

#### 1.2 핵심 요구사항
- **FR-1/FR-2**: Diff 계산을 파일워칭/초기화 타이밍이 아닌 **이미지 로드 성공 이후**에만 수행
- **FR-3**: Diff 계산에 필요한 치수는 **미디어 로드 성공을 만든 동일 입력**에서 얻어야 함 (파일 재오픈 금지)
- **FR-3.2**: 썸네일 캐시 히트 경로에서도 원본 치수가 제공되어야 함
- **FR-9**: 스테일(늦은) 이벤트로 인한 UI 오염 방지 (GroupId/LoadSessionId 검증)

#### 1.3 설계 문서 작성
- **계획** (`03_plan.md`): 아키텍처 개요 및 데이터 흐름 정의
- **디자인** (`04_design.md`): 상세 컴포넌트 설계
  - `MainImageLoadedInfo` record 타입 정의
  - `IImageProcessor.GenerateThumbnailWithDimensionsAsync` API 확장
  - `FileGroupMediaLoader`의 단일 프로퍼티로 원자적 업데이트
  - `FileGroupViewModel.CalculateAbnormalStatusFromLoadedInfo` 메서드 설계
- **작업 목록** (`tasks.md`): 9개 주요 작업 항목 정의

#### 1.4 핵심 설계 결정
- **단일 진실 소스(SSoT)**: `MainImageLoadedInfo` 프로퍼티로 로드 성공 정보 제공
- **제로 추가 I/O**: 동일 이미지 디코딩 과정에서 원본 치수 추출
- **캐시 정합성**: 썸네일 캐시에 원본 치수도 함께 저장하여 캐시 히트 시에도 Diff 계산 가능
- **스테일 가드**: `GroupId`/`LoadSessionId` 검증으로 늦은 이벤트 필터링

### 2. 삭제 로직 정제 (refine_delete_intersection)

#### 2.1 문제 분석
- **문서**: `docs/spec/refine_delete_intersection/03_plan.md`, `04_design.md`
- **문제점**: 
  - "Row Selection"과 "Component Selection"의 교집합이 엄격히 강제되지 않음
  - UI 확인 메시지가 실제 삭제 대상과 일치하지 않을 수 있음

#### 2.2 설계 결정
- **Row Gate 로직**: `GetSelectedComponents()`와 `GetSelectedComponentDetails()`에서 `IsSelected=false`일 때 빈 리스트 반환
- **XAML 바인딩 강화**: `CheckBox` 바인딩에 `Mode=TwoWay, UpdateSourceTrigger=PropertyChanged` 추가
- **SSoT 정의**: 
  - Row Selection: `DataGridRow.IsSelected` (TwoWay-bound to `FileGroupViewModel.IsSelected`)
  - Component Selection: `IsNormalSelected`, `IsNirSelected`, `IsCam1Selected` 등

#### 2.3 작업 목록 작성
- **문서**: `docs/spec/refine_delete_intersection/05_tasks.md`
- **구현 단계**: 
  - `SharedResources.xaml` 바인딩 업데이트
  - `FileGroupViewModel.cs`의 선택 메서드에 Row Gate 추가
  - 삭제 확인/실행 로직 검증

### 5. GroupManager 컬럼 내 순서성 체크 로직 개선

#### 5.1 구현 내용
- **파일**: `ChronoView/Core/FileWatching/GroupManager.cs`
- **위치**: `FindMatchingExistingGroup` 메서드 내부 (라인 606-620)
- **변경사항**:
  - 컬럼 내 순서성 체크 로직 추가
  - 마지막 배정 그룹보다 이후 그룹만 매칭 허용
  - 라인별 분리된 추적 (`_lastAssignedGroup` Dictionary 키: `(DataType, LineNumber)`)
  - UI 로그 추가: 컬럼 순서 위반 시 `[매칭제외]` 로그 출력

#### 5.2 핵심 로직
```csharp
// ★ 컬럼 내 순서성 체크: 마지막 배정 그룹보다 이후 그룹만 허용 (라인별 분리)
var sequenceKey = (newGroupType, newGroup.LineNumber);
if (_lastAssignedGroup.TryGetValue(sequenceKey, out var lastGroupId))
{
    if (CompareGroupId(candidate.GroupId, lastGroupId) <= 0)
    {
        // UI 로그 추가 - 컬럼 내 순서성 위반
        RaiseLog($"[매칭제외] {colName}: {fileName} -> {candidate.GroupId} 제외 (사유: 컬럼순서 위반, 마지막배정: {lastGroupId}, 후보기준: {candAnchorFile}@{candAnchorTime})", newGroup.LineNumber);
        continue;
    }
}
```
