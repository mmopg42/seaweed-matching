# 로그 개수 불일치 원인 분석 보고서

## 1. 분석 결과
UI 로그와 Debug(파일/콘솔) 로그의 개수가 일치하지 않는 원인은 크게 두 가지입니다.

### A. 로그 수집 범위의 차이 (설계된 의도)
이것은 버그가 아니라 프로그램의 설계 의도에 따른 정상적인 동작입니다.

*   **Debug 로그 (`ChronoView_Debug_...log`)**:
    *   **범위**: 애플리케이션의 **모든** 동작을 기록합니다.
    *   **출처**: `ILogger`를 사용하는 모든 서비스와 모듈에서 발생하는 로그가 포함됩니다. (예: 내부 로직 수행, 변수 값 변화, 상세 흐름 등)
    *   **목적**: 개발자가 문제를 추적하고 해결하기 위한 상세 기록용입니다.

*   **UI 로그 (`ChronoView_UI_...log` 및 화면 표시)**:
    *   **범위**: 사용자에게 의미 있는 **주요 이벤트**만 기록합니다.
    *   **출처**: ViewModels나 Orchestrator에서 명시적으로 `AddLogMessage`나 `LogRequested`를 호출한 경우에만 기록됩니다. (예: "이동 작업 완료", "파일 감지됨", "오류 발생")
    *   **목적**: 사용자가 현재 프로그램의 상태를 파악하기 위한 요약 정보용입니다.
    *   **결과**: 따라서 UI 로그의 개수는 Debug 로그보다 훨씬 적을 수밖에 없습니다.

### B. UI 로그 파일 분할 버그 (발견된 문제)
분석 도중 **심각한 버그**가 발견되었습니다. UI 로그 파일이 하나로 유지되지 않고, 로그가 기록될 때마다(초 단위로) 새로운 파일로 분리되어 생성되고 있습니다.

*   **원인 코드**: `MainWindowViewModel.cs`의 `WriteToUILogFile` 메서드
    ```csharp
    // 메서드가 호출될 때마다 DateTime.Now를 새로 가져옴
    var startTime = DateTime.Now; 
    // 매번 새로운 초(Second) 단위의 파일명을 생성함
    var logFile = Path.Combine(dateFolder, $"ChronoView_UI_{startTime:yyyyMMdd_HHmmss}.log");
    ```
*   **증상**: 로그 폴더에 `ChronoView_UI_20250107_120001.log`, `ChronoView_UI_20250107_120002.log`와 같이 수많은 파일이 생성될 수 있습니다.

## 2. 해결 방안
### 범위 차이 (A)
*   정상적인 동작이므로 수정할 필요가 없습니다. 사용자에게는 "UI 로그는 중요 알림 위주이며, 전체 상세 로그는 Debug 로그 파일을 확인해야 한다"고 안내하면 됩니다.

### 파일 분할 버그 (B)
*   **수정 필요**: 로그 파일 경로를 한 번만 생성하고, 애플리케이션 실행 동안 계속 재사용하도록 `MainWindowViewModel.cs`를 수정해야 합니다.

## 3. 조치 계획
1.  `MainWindowViewModel.cs`를 수정하여 로그 파일 경로를 캐싱(static 변수 활용)하도록 변경합니다.
2.  이후 재실행하여 로그 파일이 하나로 유지되는지 확인합니다.
