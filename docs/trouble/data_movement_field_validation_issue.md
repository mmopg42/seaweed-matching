# 데이터 이동 필드 값 인식 문제 원인 분석 보고서

## 1. 문제 개요
사용자가 "이동 설정" 패널의 **전체 데이터 이동** 필드에 값(예: 10)을 입력하고 상단 툴바의 **이동** 버튼을 클릭했으나, "전체 데이터 이동 필드에 값이 없습니다"라는 경고 메시지가 표시되며 값이 인식되지 않는 현상이 발생합니다.

## 2. 원인 분석
WPF의 `TextBox.Text` 속성에 대한 바인딩은 기본적으로 `UpdateSourceTrigger=LostFocus`로 설정되어 있습니다. 이는 해당 입력 필드가 **포커스를 잃을 때** (다른 컨트롤을 클릭하거나 Tab 키로 이동할 때) ViewModel의 속성 값을 업데이트한다는 의미입니다.

그러나 본 애플리케이션의 구조상 다음과 같은 이유로 업데이트가 트리거되지 않았습니다:

1.  **입력 위치**: `WorkflowPanel` 내의 TextBox에 값을 입력합니다.
2.  **명령 실행**: 상단 `ToolBar`에 있는 **이동** 버튼을 클릭합니다.
3.  **포커스 동작**: WPF의 **ToolBar 버튼**은 클릭 시 기본적으로 **포커스를 가져가지 않는(Focusable=False) 특성**이 있습니다.
4.  **결과**: 사용자가 버튼을 클릭해도 여전히 TextBox에 포커스가 남아있는 상태로 간주되거나, `LostFocus` 이벤트가 발생하기 전에 명령(Command)이 먼저 실행됩니다.
5.  **현상**: View의 TextBox에는 "10"이 보이지만, ViewModel의 `MoveAllData` 속성은 여전히 빈 값("") 상태이므로 유효성 검사에서 실패합니다.

## 3. 해결 방안
`WorkflowPanel.xaml` 파일의 TextBox 바인딩 설정에 `UpdateSourceTrigger=PropertyChanged`를 추가합니다. 이렇게 하면 사용자가 키를 입력할 때마다 즉시 ViewModel의 속성 값이 업데이트되므로, 포커스 변경 여부와 관계없이 항상 최신 값을 유지할 수 있습니다.

### 수정 대상
*   `WorkflowPanel.xaml`
    *   **시료명** (SampleName)
    *   **NIR 이동** (MoveNir)
    *   **전체 데이터 이동** (MoveAllData)

모든 입력 필드에 동일한 문제가 발생할 수 있으므로 일괄 적용합니다.

## 4. 검증 계획
수정 후 값을 입력하고 포커스를 이동하지 않은 상태에서 바로 이동 버튼을 클릭하여 경고 메시지 없이 정상적으로 로직이 수행되는지 확인합니다.
