# Data Simulator - Timestamp-based File Move Tool

실제 데이터 생성 타이밍을 재현하여 ChronoView 모니터링을 테스트하기 위한 시뮬레이터입니다.

## 기능

- 소스 폴더의 모든 파일/폴더에서 타임스탬프 추출
- 추출된 타임스탬프 순서대로 정렬
- **타임스탬프 순서대로 파일 이동** (같은 드라이브 = 즉각 rename)
- Reset 기능으로 원본 위치로 복원 가능
- 폴더 구조 유지
- GUI로 간편한 조작

## 지원하는 데이터 형식

### NIR 파일 (`nir/`)
- 형식: `run_120251201T140542.spc`, `run_120251201T140542A.txt`
- 타임스탬프 위치: `T` 다음 6자리 (`HHMMSS`)

### Normal 폴더 (`normal/`)
- 형식: `C251201T140543_0/`
- 타임스탬프 위치: `T` 다음 6자리 (`HHMMSS`)

### Camera 파일 (`cam1/`, `cam2/`, `cam3/`)
- 형식: `20251201_140548_897.bmp`
- 타임스탬프 위치: 첫 번째 `_` 다음 6자리 (`HHMMSS`)

## 사용 방법

### 1. 실행
```bash
python data_simulator.py
```

### 2. 설정
1. **Source Folder**: 원본 데이터 폴더 (기본값: `Z:\윤태경\seaweed\program\data\2025_A046`)
2. **Target Folder**: 복사할 대상 폴더 (Browse 버튼으로 선택)

### 3. 시뮬레이션 시작
1. `Start Simulation` 버튼 클릭
2. 5초 카운트다운 후 시작
3. 각 파일/폴더가 타임스탬프 순서대로 복사됨

### 4. 초기화
- `Reset Target Folder` 버튼: 타겟 폴더의 모든 내용 삭제 (재테스트용)
- `Stop` 버튼: 실행 중인 시뮬레이션 중지

## 동작 원리

### 파일 이동 (Move)
1. 소스 폴더에서 모든 파일/폴더 스캔
2. 각 항목에서 타임스탬프 추출
3. 타임스탬프 기준으로 정렬
4. 첫 번째 항목의 타임스탬프를 t0로 설정
5. 각 항목을 `(항목_타임스탬프 - t0)` 만큼 대기 후 이동
6. `os.rename()` 사용 (같은 드라이브 = 즉각 이동, ~0.0001초)

### 예시
```
[Scheduled Move - 타임스탬프 순서대로]
T+0.0s: Z:\원본\nir\run_120251201T140542.spc → Z:\시뮬\nir\ (0.0002초)
T+1.0s: Z:\원본\normal\C251201T140543_0/    → Z:\시뮬\normal\ (0.0005초)
T+6.0s: Z:\원본\cam1\20251201_140548_897.bmp → Z:\시뮬\cam1\ (0.0001초)
```

### 핵심 원리
- **같은 드라이브 내 이동 = rename operation** (파일 데이터 복사 없음)
- `os.rename()` 사용으로 최고 속도
- 파일이 나타나는 시점 = 정확한 타임스탬프 유지
- 원본 파일이 이동되므로 Reset으로 복원 필요

### Reset 기능
- 이동된 파일들을 원래 위치로 다시 이동
- 역순으로 이동하여 폴더 구조 복원
- 원본 데이터 완전 복구

## 요구사항

- Python 3.7+
- tkinter (Python 기본 라이브러리)
- 표준 라이브러리만 사용 (추가 설치 불필요)

## 테스트 시나리오

### 기본 테스트 (같은 드라이브)
1. Data Simulator 실행
2. Source와 Target을 **같은 드라이브**로 설정 (예: 둘 다 Z:)
   - Source: `Z:\윤태경\seaweed\program\data\2025_A046`
   - Target: `Z:\윤태경\seaweed\program\data\시뮬`
3. ChronoView 실행 및 `Z:\...\시뮬` 모니터링 시작
4. Data Simulator에서 `Start Simulation` 클릭
5. 즉시 시작됨 (대기 시간 없음!)
6. ChronoView에서 실시간으로 파일 그룹이 타임스탬프 순서대로 생성되는 것 확인
7. 썸네일 로딩 속도 관찰
8. 테스트 완료 후 `Reset`으로 원본 복원

### HDD vs SSD 비교 테스트
같은 드라이브 조건에서 ChronoView 성능 비교:
- Z: (네트워크 HDD) vs C: (로컬 SSD)
- 썸네일 로딩 속도 차이 측정

## 주의사항

- ⚠️ **Source와 Target은 반드시 같은 드라이브여야 함** (다른 드라이브 = 복사 발생)
- ⚠️ **원본 파일이 이동됨** - 시뮬레이션 후 Reset 필수!
- Reset 없이 재실행 시 파일이 없어서 에러 발생
- Stop 버튼으로 언제든지 중지 가능
- Reset으로 원본 위치 완전 복구 가능

## 트러블슈팅

### "No files to reset" 메시지
- 시뮬레이션을 아직 실행하지 않음
- Start Simulation 후 Reset 가능

### 파일이 없다는 에러
- 이전 시뮬레이션 후 Reset하지 않음
- Reset 버튼으로 파일 복원 후 재시도

### 이동이 느림 (0.01초 이상)
- Source와 Target이 다른 드라이브
- **반드시 같은 드라이브로 설정** (rename operation 필요)

### 타임스탬프 간격이 부정확
- ±0.1초 오차는 sleep() 해상도 한계
- 전체 타임스탬프 간격은 정확히 유지됨
